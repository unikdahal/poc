### Mechanisms and controls

**FACT.** TPC-DS Q77 moved two rows at zero-based positions 1 and 2. Both rows sort on `('catalog channel', NULL)`. The full output had the same multiset. The reduced query with an explicit secondary order matched. This is a permitted tie ordering. [Rows and tie keys](https://github.com/unikdahal/poc/blob/10f1c46405e46b4aea792ed502aa872f5c89ac02/pinned/result.json)

**FACT.** Decimal AVG changed the last retained digit without changing the output scale. The reduced aggregate and window cases reproduce that behavior. The pinned aggregate and window resolutions call the same DataFusion average UDAF. [Aggregate](https://github.com/lakehq/sail/blob/790c622e5c4d9a9e2b87bdfb8e5cb5a3a720035f/crates/sail-plan/src/function/aggregate.rs#L67-L85) · [Window](https://github.com/lakehq/sail/blob/790c622e5c4d9a9e2b87bdfb8e5cb5a3a720035f/crates/sail-plan/src/function/window.rs#L102-L130) · [Typed output](https://github.com/unikdahal/poc/blob/10f1c46405e46b4aea792ed502aa872f5c89ac02/pinned/result.json)

**FACT.** The decimal division path delegates the binary expression and carries a TODO for Spark precision and scale. TPC-H Q8 and Q14 used different output scales. Q17 had the same scale and differed by one unit at scale six. Q66 also differed at equal scales. [Division code](https://github.com/lakehq/sail/blob/790c622e5c4d9a9e2b87bdfb8e5cb5a3a720035f/crates/sail-plan/src/function/scalar/math.rs#L437-L447) · [Typed output](https://github.com/unikdahal/poc/blob/10f1c46405e46b4aea792ed502aa872f5c89ac02/pinned/result.json)

**FACT.** The CTAS with session zone `Etc/UTC` failed with `Timezone must be UTC or +00:00`. Spark wrote and read back the timestamp. Changing the Sail session zone to `UTC` let the same CTAS and readback succeed at an independent table location. [Timezone conversion](https://github.com/lakehq/sail/blob/790c622e5c4d9a9e2b87bdfb8e5cb5a3a720035f/crates/sail-iceberg/src/datasource/type_converter.rs#L424-L434) · [Both controls](https://github.com/unikdahal/poc/blob/10f1c46405e46b4aea792ed502aa872f5c89ac02/pinned/result.json)

**FACT.** Parenthesizing the PIVOT identifier, spelling the arithmetic string cast explicitly, dropping the regex lookahead, using a recognized month truncation unit, passing both LOG arguments and replacing value-mapping DECODE with CASE all matched the Spark controls. [Control outputs](https://github.com/unikdahal/poc/blob/10f1c46405e46b4aea792ed502aa872f5c89ac02/pinned/result.json)

### Coverage limits

Public issue and PR searches ran separately against the upstream repository. Search terms included decimal division, decimal, AVG, bround, rounding, cast, initcap, regexp, trunc, make_date, pivot, decode, timezone, Etc/UTC, log, coercion and overflow. Public search can miss an open report. The alternate build freezes the then-current main SHA. The result applies to that SHA. SQL with explicit collation, nondefault Spark decimal precision policy, and other Spark releases had no separate treatment.
